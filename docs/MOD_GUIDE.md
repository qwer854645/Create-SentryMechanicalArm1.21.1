# 当前模组完整介绍

适用于 **1.4.0-alpha.41**。本文介绍现行玩法、操作、配置与兼容边界。

## 1. 定位与运行环境

这是 Create: Sentry Mechanical Arm 的非官方 1.21.1 NeoForge 修复开发分支。核心玩法是让哨戒动力臂使用 TaCZ 枪械自动防御，并将弹药生产、射击补给、弹壳回收接入 Create 物流。

目前形成三部分：

- 自动防御：哨戒动力臂、枪械射击、弹药补给、火控名单与集火指示。
- 工业制造：口径模具制造新壳，流态火药装药，单发序列装配还原枪包弹药。
- 射后回收：按枪包识别弹壳，动力臂收集器入库，玩家背包收集，以及可自定义的射后产物。

运行目标为 Minecraft 1.21.1、Java 21、Create 6.0.10、官方 TaCZ 1.2.0。模组元数据要求 NeoForge 21.1.228 或以上。Create 与 TaCZ 在元数据中固定上述版本，不能据此推断适用于其他大版本。

JEI 为可选显示集成。Create JEI Compat 1.0.3 可用于较长序列装配的分页，但只能安装在客户端，不能放进独立服务端；它不内嵌，也不是强制前置。Sable Companion 1.6.0 随包内嵌；实际 Sable 和机械动力航空学不是普通静态玩法的必需内容。

## 2. 哨戒动力臂

### 放置、装枪与动力

哨戒动力臂可由一个 Create 动力臂与一个精密构件无序合成。它属于动力方块，需要有效转速才能持续工作；失去动力后停止射击，避免已排队连发继续开火。注册的应力影响系数为 3.0，实际负载按 Create 转速计算。

装枪使用 **TaCZ 的交互键，默认 O**：手持枪械对准动力臂进行交互。取下已装备枪械可使用右键交互。具体按键以玩家自己的 TaCZ 键位设置为准，不将装枪简单描述成普通右键。

炮台默认扫描射程内的敌对生物，进行目标选择、视线判断、转向与开火。射程通过 Create 滚轮数值行为调整；上限结合枪械数据计算，最高不超过 256 格，因此不是所有枪都固定拥有 256 格射程。动力转速也参与关节追踪动画速度。

枪械射击接入 TaCZ 操作者，处理半自动、自动、连发、栓动与充能等不同状态，并同步枪械弹药和配件数据。枪口位置、方向和移动结构坐标已有专门处理；火箭、榴弹等实体弹道武器沿用原生弹道，避免叠加普通枪械的显示轨迹。第三方枪包若使用额外脚本或非标准模型，仍可能需要回退或继续修复，不能把“已接入”理解为任意枪包无条件兼容。

### 弹药补给

每个动力臂最多附加两个 TaCZ 弹药盒。持盒右键装入，潜行右键取下；已装枪时会检查弹药兼容性。供弹逻辑也接入相邻库存、Create 移动结构库存及 TaCZ 弹药库，移动弹药库使用专门的存储适配保留大数量数据。

这里区分三种用途：弹药盒随炮台携带，弹药库保存和供应未发射弹药，弹壳收集器接收射后产物。普通箱子可以参与既有供弹或战利品库存逻辑，但不会自动替代专用弹壳收集器。

### 外观与战利品

动力臂保留染色交互，染料用于着色，水桶用于清除颜色。此处的水桶只是外观交互，不参与流态火药生产。

还保留静态炮台的击杀战利品接入：对能追溯到该炮台的击杀，尝试将掉落物送入其正下方的物品容器；经验事件会按代码规则换为附魔之瓶尝试入库。该路径不为 Create 虚拟移动炮台记录击杀位置，不应作为移动结构通用战利品回收承诺，也不同于新弹壳收集器。

## 3. 火控系统

### 拉特兰火控台

内部 ID 为 `blaze_fire_control`。通过扳手交互将火控台与动力臂建立连接，向多个炮台提供统一目标规则。火控台可插入一份“跨境追缉许可”，空手交互取出；动态结构也有对应的名单库存与交互实现。

### 跨境追缉许可

内部 ID 为 `fire_control_clipboard`，是一份可编辑目标名单。手持右键打开界面，潜行右键把自己加入名单；主手使用原版望远镜、副手持许可时，可用中键记录远处实体。

当前界面的两种模式含义是：

- 白名单（安全列表）：名单中的目标安全，其他目标按该模式规则攻击。
- 黑名单（攻击列表）：名单中的目标被攻击，其他目标安全。

不要将白名单理解成“只攻击名单里的生物”。使用前应按这个实际语义配置。

### 哨戒瞄准镜

潜行右键火控台进行绑定，再次对同一台操作可解绑。右键使用瞄准镜放大，使用期间左键标记实体目标，中键标记坐标，以指引连接炮台集火。坐标攻击只给符合爆炸武器识别条件的炮台使用，不会让所有普通枪械无条件射击标记点；标记也不能绕过炮台自身距离和射击条件。

### 附属内容

保留拉特兰苹果派等原有主题物品。火控台接受苹果派并播放进食/爱心反馈，目前没有据此声明额外战斗增益。

## 4. 移动结构与物理结构

已实现普通方块状态与 Create Contraption 虚拟状态的不同处理路径，覆盖移动结构、矿车与列车。枪械状态、供弹、火控、枪口投影与结构库存均有对应实现；动态结构底部齿轮的变换也经过此前修复。

Sable／Create: Aeronautics 使用子结构与世界坐标之间的变换，处理扫描、瞄准、枪口、玩家距离和收集器归属。VS2 保留可选反射适配路径，不要求普通用户安装 VS2。

“同结构”具有实际边界：Create 使用同一个 Contraption；Sable 使用同一个子结构 UUID；可选 VS 路径使用船体 ID。收集时不会因为世界坐标靠近而把另一艘船的收集器当作自己的。

移动收集器支持结构库存保存与拆装回写。多船并行、长期跨区块和所有物流组合尚未穷尽，VS2 未安装实测，不作为已验证支持。

## 5. 自动弹壳体系

### 自动识别与数据

从已加载 TaCZ 弹药和显示数据中识别实体弹壳，结合壳体模型/材质信息与排除规则，默认排除不适合回收壳体的火箭、能源、特殊无壳弹药等。识别采用通用规则，不按某个测试枪包单独硬编码；显式数据包可以覆盖识别结果。

所有口径共用注册物品 `sentrymechanicalarm:empty_casing`，通过持久化、可网络同步的数据组件记录对应弹药 ID。它们是一个注册物品的不同口径变体，而不是为每个枪包新增一批固定物品注册项。相同口径的新制壳与回收壳可直接堆叠。

再装填半成品使用 `reloading_casing`，同时记录口径与 Create 序列进度，最大堆叠为一。

### 外观与物品查询

物品名、提示和分类尽量沿用 TaCZ 弹药的命名方式，能够反映原弹药名称与来源。默认图标由原弹药贴图按当前 38% 裁切参数生成，地面显示也有对应适配；已修复额外变暗问题。自动取图无法保证所有复杂枪包都得到理想壳体形状。

创造模式有独立的 `TAC | 弹壳` 标签页，使用 9mm 弹壳作为图标，放在 TaCZ 弹药栏之后、其他物品栏之前。

JEI 已按口径组件区分弹壳、半成品与模具，避免所有口径被认作同一个配方输入。侧栏只列一个空白模具，具体制造配方仍显示对应口径的模具；不会用大量模具变体淹没物品列表。

### 产出条件

回收物来自确认消耗有限弹药的射击过程。创造模式、无限弹药及不受支持的其他 FakePlayer 不作为免费产物来源。玩家、动力臂、其他生物分别受开关控制；其他生物选项只监听符合条件的射击，不会给生物新增持枪或射击 AI。

默认每次符合条件的射击事件产出一枚对应弹壳，数据包可以改成其他口径、其他物品、数量或概率。

## 6. 弹壳与子弹制造

### 制造新壳

使用两个铁锭和一根木棍合成口径模具。手持右键打开口径选择界面，支持名称或弹药 ID 搜索与分页；可选列表由服务器当前实际制壳配方决定。

机械手持已设置口径的模具加工对应金属，得到该口径新壳。模具不消耗、不磨损，可重新选择口径。当前模具为平面 16×16 像素贴图，没有使用精细立体模型。

制壳的输入可能是金属粒、锭或块，产量为固定整数，不应继续按早期文档理解为“所有口径都用一粒铜”。没有可识别原方金属时，可启用通用铜粒后备规则，默认一粒一壳；有明确成本但无法表达的配方，不会借后备规则廉价绕过。

能够回收弹壳，不等于必定有自动制壳配方；能够制壳，也不等于必定能自动推导完整子弹配方。

### 无水流态火药

一份原版火药经搅拌得到 1000 mB 流态火药，不加水、不要求加热。它是供 Create 加工、储存和管道运输使用的工艺流体，没有可放置的世界流体方块和流体桶。

每发自动装药量为：

`ceil(原配方火药总量 × 1000 ÷ 原配方弹药产量) mB`

没有六档区间，不添加底火预留量。正数自然向上取整到至少 1 mB；超过注液器单次 1000 mB 容量时拆成多次注液，总消耗不变。整个装配仍受最多 16 道工序等表达上限约束，不保证任意超高成本原方都可自动生成。

### 单发再装填

当前流程为：

**一枚同口径弹壳 → 注入流态火药 → 机械手投入所需固体 → 冲压 → 一发原枪包弹药。**

无流体或无某项固体费用时省略对应步骤。输入单壳、输出单发，不引入“成组弹壳”。青金石、红石等可解析特殊配料保留，不因简化流程被自动改成普通铜。

相邻相同的普通消耗材料会合并成一次定量投放，缩短长配方。比如某一步需要四粒铜，机械手须有足够数量后一次支付，数量不足时等待；不会推进进度而少扣材料。复杂工具、带返还容器或组件语义的原料不盲目合并。

### 成本与回收收益

自动规则把铜、铁、金换算成金属粒单位：粒 1、锭 9、块 81。按铜优先、其次铁、再其次金选主金属。默认再装填主金属系数为 0.5；其他弹体金属保留原成本，每发不足一粒的金属按既定规则省略，其余向上取整。

新壳承担“原方每发主金属成本减去实际再装填主金属费用”的预算。程序在粒、锭、块与 1–64 枚固定产量间选择尽量贴近预算的方案，使回收壳省去制壳成本，而新制整发不因制壳规则被大幅压价。

依据默认原方和代码计算，9mm 是一锭铜制造五壳，每壳注入 40 mB 后冲压；5.56 是一粒铜制造一壳，再装填投入两粒铜与 67 mB 流体；12g 是一个铜块制造 23 壳，再装填投入四粒铜、一粒铁与 334 mB 流体。这些是规则推算例子，数据包或原方变化后以实际 JEI 配方为准，也不是本次运行验收结果。

成本保护针对可理解的材料数量和主金属，不把各类材料折为统一货币。特殊配料向上取整、微量金属省略及显式自定义，都会影响最终价值；无法宣称每个口径总价值严格等于或低于原方。

### 半成品与旧原方

自动再装填配方带成本指纹。材料或流体费用变化后，旧半成品不能沿旧费用继续完成新规则；可单独放入合成栏取回弹壳，已投入材料不退。

部分枪包仍使用旧 `data/<namespace>/recipes/` 目录，而 1.21.1 使用 `recipe/`。当前会将能严格转换的旧 TaCZ 弹药配方恢复为原生工作台配方，保留材料、产量、分组与 ID，现代配方优先。条件、NBT、组件或未知材料复杂到无法可靠转换时跳过，不猜测免费配方；工作台自身分类过滤依然有效。

## 7. 弹壳收集器与玩家回收

### 动力臂收集

新增 `sentrymechanicalarm:casing_collector`，27 格普通库存。材料是一个箱子、两个安山合金、两个铁锭。右键打开三行容器界面，支持普通物品接口、漏斗、Create 物流和比较器，拆除正常掉出库存。

无需为动力臂另开收集配置：

- 静态动力臂查找六个面相邻的弹壳收集器。
- Create 动态结构查找同一结构内的收集器，按距离优先。
- Sable／航空学按同一子结构查找已加载收集器。
- 多个收集器可依次接收；没有收集器或全部满载，剩余部分继续落地。

流程是直接存入本次射后产物，不会先生成地面实体再吸走，也不会吸取附近已有物品。自定义的其他射后物品同样可以存入，数据组件予以保留。查找不会强制加载远方区块。

Create 移动库存使用专门的 MountedStorage 类型接入保存、便携式存储接口及拆卸回写，射击只写当前移动库存。该部分已完成实现，仍需当前版本游戏内验收。

收集器外观为完整安山机壳加顶部漏斗背面薄面板。选框和碰撞覆盖机壳与薄面板。贴图继续只引用 Create 资源，没有复制 PNG。

游戏内提供简介、后勤、移动、火控、制壳、流态装药再装填、弹壳收集、弹药库补给和瞄准镜指挥九段思索，可从对应物品进入。

### 玩家收集

`casings.playersToInventory` 默认开启：射后产物优先进入玩家背包。放不下的部分参考原版 `/give`，在玩家位置掉出、没有拾取延迟并指定玩家为拾取目标；不额外套用弹壳实体上限而吞掉溢出物。

设为 false 恢复玩家地面抛壳。`players=false` 则完全不生成玩家回收物，不能把它当成“关闭背包、改落地”。其他生物仍走地面输出。

普通地面弹壳默认每区块最多 64 个相关物品实体，寿命 1200 游戏刻（正常 20 TPS 下约一分钟）；达到上限会跳过多余地面输出。成功入库不创建实体，先收集后处理地面限制。

## 8. 自定义制造与抛壳

统一入口为服务端数据包：

`data/<弹药命名空间>/sentry_manufacturing/<弹药路径>.json`

例如 `tacz:9mm` 使用 `data/tacz/sentry_manufacturing/9mm.json`。修改后服务端 `/reload`；同一路径遵守数据包优先级整份覆盖，不跨包合并字段。

```json
{
  "enabled": true,
  "reloading": {
    "materials": [],
    "propellant": 40
  },
  "forming": {
    "input": {"item": "minecraft:copper_ingot"},
    "output_count": 5
  },
  "drops": {
    "casing": "tacz:9mm",
    "count": 1,
    "chance": 1.0
  }
}
```

根 `enabled` 控制该弹药的简化规则与适用范围。`reloading` 定义精确固体和流体费用；`forming` 定义每件投入和固定产量，模具保留；`drops` 定义目标口径或任意 ItemStack（含组件）、数量与概率。每段可以单独关闭，省略才继续使用低优先级来源。

制造来源优先级为：完整原生 Create 配方覆盖 → 统一文件对应段 → 旧自定义入口 → 原方自动推导 → 缺失金属来源时的通用制壳规则。显式自定义数量不再被自动折扣或预算重算；格式错误的显式段会停用并记录位置，不自动补回更便宜的配方。

抛壳可用 `casing` 映射到其他口径，也可用 `item` 设置普通物品，两者互斥；数量支持 0–1024、概率 0–1。映射只改变射后产物，不自动把多个弹药制造路线改成共用同一壳体。所有来源开关、有限弹药确认和创造模式限制仍保留。

完整字段、原生配方 ID 与边界见 [CUSTOM_MANUFACTURING.md](CUSTOM_MANUFACTURING.md)，模板见 [examples/manufacturing-rules](../examples/manufacturing-rules)。模板没有自动安装进存档。

## 9. 当前配置

### 启动级注册开关

文件：`config/sentrymechanicalarm-startup.toml`。

```toml
[casings]
enabled = true
```

false 时直接不注册弹壳、半成品、模具及弹壳标签页，并关闭该体系。需要重启，客户端与服务端必须一致；旧弹壳库存不能在取消注册期间保留。收集器继续作为普通存储方块存在。

### 世界级服务器配置

文件为当前存档的 `serverconfig/sentrymechanicalarm-server.toml`。单人位于对应 `saves/<世界>/serverconfig/`，独立服务器位于实际世界目录的 `serverconfig/`。以下为当前默认值：

```toml
[casings]
enabled = true
players = true
playersToInventory = true
sentries = true
others = false
dropChance = 1.0
maxEntitiesPerChunk = 64
lifetimeTicks = 1200

[reloading]
enabled = true
autoFromTaCZ = true
metalCostMultiplier = 0.5
readLegacyMaterialRecipes = true

[gunpackCompatibility]
restoreLegacyAmmoRecipes = true

[casingManufacturing]
enabled = true
allowGenericCopperFallback = true
fallbackCasesPerCopperNugget = 1
```

服务器 `casings.enabled` 是运行输出开关，与启动注册开关不同。再装填与制壳各有总开关；关闭自动推导不影响仍被允许的显式规则，关闭相应制造总开关则停止本模组生成的该类配方。配方相关配置更改后执行服务端 `/reload`。

早期 `ammo_crafting`、`dynamic_recipes` 与 `powderBands` 等方案不在当前 `SMAServerConfig` 中，不能照历史文档继续配置。本模组的制造开关也不用于删除 TaCZ 原生配方或第三方自行编写的完整原生配方。

## 10. 已移除内容与当前边界

当前已移除：旧待加工弹壳/弹药模板/铜板火药制作链，底火壳、底火、小火药及其配方，六档装药区间。底火与小火药旧库存没有迁移入口。当前只保留新弹壳、新壳制造、流态装药与再装填路线。

枪包适配采用通用规则，不为特定枪包新增专属优惠或写死口径。非标准弹药、复杂组件配方、非典型模型或没有可靠原方的数据，可能需要整合包作者通过显式规则表达。

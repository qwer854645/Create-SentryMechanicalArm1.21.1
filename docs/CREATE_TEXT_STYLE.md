# Create 原版思索与提示文案风格

## 阅读范围与来源

本次直接阅读本地运行依赖 Create **6.0.10+mc1.21.1** 的原始资源，不以其他模组或印象代替原版。来源是该 JAR 的 `assets/create/lang/zh_cn.json` 与 `en_us.json`，并对照本项目使用的 `ItemDescription.Modifier` 提示接口。

思索重点阅读动力冲压机、工作盆压缩、动力搅拌器、机械手加工、机械手模式与动态结构、注液器、漏斗方向/传输/红石、黄铜漏斗及物品保险库。提示重点阅读扳手、过滤器、属性过滤器、包裹过滤器及机械手状态信息。

代表性资源键：`create.ponder.deployer_processing.text_*`、`create.ponder.spout_filling.text_*`、`create.ponder.mechanical_press.text_*`、`create.ponder.item_vault_storage.text_*`、`item.create.wrench.tooltip.*`、`item.create.filter.tooltip.*`、`create.tooltip.deployer.*`。

以下是归纳出的写作规则，不宣称原版每一条文本都机械遵守同一长度或句式。

## 思索：配合正在发生的演示

### 先说明用途，再展示操作

常见顺序是“这个组件能做什么 → 如何输入或摆放 → 组件怎样处理 → 输出结果 → 当前画面需要的限制”。原版用可见的物品、方块和动作建立理解，不先讲内部数据、算法或版本背景。

本项目应用：制壳从选择口径和交付模具开始，随后显示金属加工；再装填依次说明搅拌、输送、注液和冲压。费用明细交给配方显示及文档。

### 一张文字卡只承担一个主要信息

短句围绕当前镜头和指示点展开。需要连续说明时，按演示步骤分卡，而不是把所有条件塞进长分号句。原版也会使用省略号把“物品经过机器”和“机器停下物品并加工”连接成前后两幕；只有镜头确实连续时才使用这种手法。

本项目建议每卡通常一至两句，中文以约 20–40 字为目标；这只是编辑参考，不是引擎限制。不要为了字数删掉必要条件，也不要把多条无关知识堆在同一卡。

### 主体、条件和结果要明确

常用“组件可以……”“将物品放在……”“使用管道……”“当……时……”等句式。描述能观察到的动作，避免只写抽象的“完整支持”“智能管理”“通用适配”。

条件限制只在帮助当前操作时出现。例如收集器满了后余量落地、移动结构使用自身库存，都是玩家布置设施所需的信息。UUID、组件序列化、配方指纹等放在开发说明中。

### 使用稳定的玩法描述

教程不讲“本版新增”“以前有底火”“不再使用模板”等开发历史。材料会被数据包改变时，不把默认费用写成普遍规律。默认 9mm 的演示物品仍可保留，但文字只说明加工关系，不要求所有口径按同一数量生产。

### 术语和语气

沿用原版中文术语：右击、潜行右击、机械手、动力搅拌器、动力冲压机、工作盆、置物台、注液器、动态结构。正文采用平实的现在时，不夸张、不替玩家评价，不反复写“你需要”“即可轻松”。英文对应使用短主动句，保持条件和结果与中文一致。

## 提示：用途、触发条件、行为

### Create 物品详细提示

原版工具常用 `summary` 概括用途，再用 `conditionN` / `behaviourN` 分组说明特定操作。它们分别回答“是什么”“何时操作”“会发生什么”。

本项目模具采用：

- 概述：让机械手将金属加工成指定口径的弹壳。
- 右击时：打开口径选择界面。
- 由机械手持有时：加工匹配的金属原料，模具保留。

模具与收集器使用 Create 原生详细提示格式及配色，按住 Shift 展开。动态状态仍独立显示，例如模具当前口径。`_重点_` 只用于 Create 的详细提示解析器，不能直接放进普通原版文字行，否则会露出下划线。

### 弹壳继续沿用弹药式提示

弹壳的提示保留既定的 TaCZ 风格：名称、简短用途、枪包来源；高级提示保留弹药 ID。不为了模仿 Create 而重复添加一整段工具说明。半成品只解释“单独合成取回空壳”和“已用材料不返还”这项实际操作。

### 状态、搜索和失败提示

状态以“对象/功能：当前状态”为主，保持短而可读。需要操作时给出直接动作，例如“请安装匹配的弹药盒”。避免在普通提示中使用“特殊组件库存已保留”“原生界面”等实现用语。ID 搜索和高级 ID 本身有实际检索用途，可以保留。

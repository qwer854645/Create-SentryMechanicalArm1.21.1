# 第二阶段：静态哨戒臂修复与回归

版本：1.4.0-alpha.3。目标依赖仍为 MC 1.21.1、NeoForge 21.1.228、官方 TaCZ 1.2.0、Create 6.0.10。
日期：2026-11-07。

## 本次修复

- 膛内还有一发时不再误判为无弹；仅特定弹种无限的创造弹药箱，也必须匹配当前枪械弹种。
- 附加弹药箱拒绝空物品、非弹药箱及不兼容的已装弹箱；手动操作和自动化共用接收规则。
- 自动化允许送入空箱，模拟插入/取出不修改库存，无效插槽不再抛出越界异常。
- 弹药箱被耗空后清除旧 AmmoId，允许重新装入不同弹种；覆盖即时装填、通用消耗与射手库存同步路径。
- 更换枪械时释放旧 FakePlayer，并重置射击等待、充能探测及缓存目标，避免同型号换枪复用旧状态。
- 拆除与区块卸载均清理射手映射。按 Create 6.0.10 的 remove 生命周期挂钩，不覆盖其 final setRemoved。
- 射手枪械状态变化后保存完整 ItemStack 组件并标记存档、同步，避免只拷贝 custom_data 且没有可靠标脏。
- 弹药箱拆装与染色由服务端执行，客户端只反馈交互，避免本地库存预测直接写入方块实体。
- 方块拆除在服务端掉落枪械、弹药箱副本并清空原槽；没有枪和箱的空闲炮塔不再每 tick 重复标脏与同步。
- 装枪数据包尊重传入的手、交互距离、旁观者状态和世界交互权限。
- 火控连接校验目标方块类型、加载状态及距离；更换连接时刷新旧控制台的连接显示。
- 开火表现包仅向本维度附近玩家发送，修正相同坐标跨维度串包。

保留 alpha.2 的 TaCZ 时钟修复以及原有即时装填规则。本次没有全面重写枪口计算、动态结构或配方系统。

## 服务端测试

可重复运行：

`./scripts/build-baseline.ps1 -JavaHome '<Java 21目录>' -UseWindowsProxy -VerifyStaticSentry`

也可运行 `./gradlew.bat -PsentrySmoke=phase2 runServer`，但必须检查日志的 PHASE2 RESULT，而不能仅看 Gradle 退出码。
构建脚本会检查失败数、失败标记以及测试是否确实完成。日志输出到 verification/phase2.log。
测试代码仅在显式启用 sentrySmoke 时编译，正常 clean build 的发布 JAR 不包含测试入口。

测试分为两部分：

1. 使用真实 TaCZ 枪械、Minecraft 物品与序列化接口，检查弹药、自动化、保存、掉落、火控及网络处理。
2. 按服务端 tick 检查索敌、射击、断电、恢复、遮挡、目标替换和耗空补弹。其中一套控制转速用于隔离状态逻辑；
   另一套实际放置 Create 创造马达、小齿轮和哨戒臂，检查真实动力网络。机械臂通过侧面的齿轮啮合驱动，不能把马达直接接到底部当作轴接口。

## 覆盖的 31 项断言组

1. 仅膛内一发仍可用。
2. 错误口径的单弹种创造箱不算可用弹药。
3. 空物品、石头等非法箱拒收。
4. 自动化空箱插入、模拟与实际提取。
5. 越界插槽不消耗物品、不崩溃。
6. 即时装填守恒并清除空箱旧弹种。
7. 自动化不能取走尚有弹药的箱子。
8. 同型号换枪重建射手，使用新枪弹量。
9. 方块移除释放射手映射。
10. 压缩 NBT 写盘再读取，保留枪械组件、箱子、颜色、射程和有效火控连接。
11. 方块实体数据包读取后保留枪械组件、弹药与设置。
12. 拒绝连接空气。
13. 区块卸载回调释放射手且保留物品数据。
14. 实际破坏方块，只掉落一把枪与一个弹药箱，且组件、弹量不变。
15. 火控攻击名单、保护名单和显式集火选择符合当前规则。
16. 开火包编码解码保持弹药数据及动作一致。
17. 同维度近处玩家收到包，远处与其他维度的同坐标玩家不收到。
18. 装枪处理正确使用副手，拒绝超距与旁观者操作。
19. 实际 Create 马达和小齿轮向放置的炮塔供能并开火。
20. 控制转速的炮塔获得敌对目标并开火。
21. 实际 GunFireEvent 次数与有限弹药减少量相符，覆盖自动装填。
22. 真实马达停机后放置炮塔停止射击。
23. 控制转速归零后不继续消耗弹药。
24. 真实马达恢复转速后放置炮塔恢复射击。
25. 控制转速恢复后恢复射击。
26. 实体墙遮挡后不持续射击。
27. 拆掉遮挡后重新索敌射击。
28. 移除原目标后找到新目标。
29. 枪和箱都空时进入无弹状态。
30. 后续补弹唤醒炮塔。
31. 补弹后的实际开火次数仍与弹药减少量相符。

## 验证范围与限制

- 武器回归使用默认 Glock 17。不能将结果扩展为全部枪包、充能、栓动或发射器均已验证。
- 目标固定且设为无敌，以隔离弹药和状态行为；本阶段没有以此宣称伤害、枪口及命中位置准确。
- 网络收包范围使用服务端的记录型玩家对象验证；不是两台真实客户端联机画面验收。
- 保存验证包括磁盘往返、区块卸载回调与组件同步；没有进行真实玩家旧存档迁移测试。
- 客户端实际装拆、模型与动画仍需要玩家场景确认。Sable 与动态结构留到后续阶段。
- 原始测试中调整过夹具：增加有限弹药、固定受击目标位置、按实际齿轮接口连接马达，避免将弹药耗尽、击退出界或接线错误当成产品缺陷。

这是静态使用流程的可测试修复版，仍属于 alpha。

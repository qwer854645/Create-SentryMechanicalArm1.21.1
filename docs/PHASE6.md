# TaCZ 新弹药库补给兼容（alpha.7）

固定环境：Minecraft 1.21.1、NeoForge 21.1.228、Create 6.0.10、官方 TaCZ 1.2.0。兼容测试额外加载航空学整合包 1.3.2 和 Sable 2.0.3。

## 使用方式

支持 TaCZ 的铁、金、钻石弹药库：`tacz:ammo_storage`、`tacz:ammo_storage_gold`、`tacz:ammo_storage_diamond`。

1. 给哨戒动力臂装枪，并挂载至少一只普通弹药盒；空盒可以使用。
2. 静态方块、Sable 船载方块：把弹药库放在机械臂六面相邻的一个位置。每秒检查一次，自动用当前枪械对应的标准弹药补充挂载盒。
3. Create 动态结构和列车：把弹药库装到同一结构或车厢中，机械臂从该结构提供的共享物品库存补给。多只机械臂可以共享同一弹药库。
4. 弹药库仍使用 TaCZ 原生界面装入、取出弹药。移动期间承担自动供弹，暂不提供移动弹药库的原生界面；拆卸后可重新打开。

本次不把大弹药库挂到机械臂原有的两个小盒槽，也不直接替代枪械的装弹、拉栓和射击逻辑。供弹先进入挂载盒，再沿既有 TaCZ 控制器装弹。

护目镜信息新增补给状态：需要兼容挂载盒、挂载盒已满、缺少对应库存、仅有特殊组件弹药、已补充、无限弹药盒。状态通过既有方块/actor 状态同步保存。

## 实现

- 静态相邻查询通过 NeoForge 物品能力获取弹药库库存，不加载远处区块。Sable 使用同一船内方块坐标查询相邻库存。
- 为三个方块注册专用 Create MountedItemStorage；通用回退只接纳普通 ItemStackHandler，不能直接用于 TaCZ 的特殊库存。
- 移动库存保留完整 ItemStack 样本组件和 long 数量，遵循总组数容量与最多 27 条目限制，支持模拟插入/提取。
- 序列化和拆卸回写不通过普通堆栈容器中转，避免大数量截断。拆卸时覆盖当前 Entries，并保留弹药库其余方块实体数据。
- 转移只在服务端执行。先模拟可提取量，按实际提取数量补盒；工作量有上限，多臂依次处理同一权威库存。
- 自动装入旧盒的弹药必须与 TaCZ 标准弹药样本的物品及组件完全一致。不同组件的同口径弹药保留原样，不自动压成旧盒里的“口径＋数量”；护目镜提示特殊组件库存。
- 使用 Create 列车自身的货舱保存链路；完整 Train 写入/读取测试验证库存，不能只用 CarriageContraption 的结构 NBT 判断列车货舱是否保留。

## 验证结果

- 新弹药库专用服务器测试：42 组通过，0 失败。包含三种等级、模拟与容量、组件样本、超过 int 范围的库存往返、满盒、缺盒、错误创造盒口径、拒绝提取、特殊库存跳过。
- 三种等级均完成真实静态供能射击、双机械臂共享旋转结构供弹、结构 NBT 往返及实际拆卸库存恢复。
- Sable 真实船载方块完成相邻弹药库补给、倾斜旋转射击、实际伤害与弹药守恒验证。测试暂停重力物理并更新船体姿态，未覆盖高速自由飞行。
- 原生列车弹药库测试：46 组通过，0 失败。直线、斜向吊装、上坡、弯道，覆盖倒车、停车、持续供弹、真实伤害、完整列车货舱保存与特殊组件保留。
- 第二阶段静态回归 31 组通过；第三阶段枪械回归 68 组通过。
- 客户端库存 codec、补给状态与中英翻译检查通过；68 个标准模型、4 种枪械安装矩阵、24 种齿轮姿态和 4 次完整渲染调用通过。2 个既有回退枪械模型跳过。

## 复现

```powershell
./scripts/build-baseline.ps1 -JavaHome 'C:/Program Files/Java/jdk-21' -VerifyAmmoDepot
./scripts/build-baseline.ps1 -JavaHome 'C:/Program Files/Java/jdk-21' -VerifyTrainDepot
./gradlew.bat -PsentryClientSmoke runClient --console=plain
```

本地运行目录装有 Sable 时不要重复通过 SableJar 添加同一个模组。未装 Sable 时，弹药库测试会跳过船载场景，测试组数会减少。

## 发布与边界

客户端与服务器均需更新 alpha.7，并删除旧版 JAR。网络协议升级为 4；新移动库存类型需要两端一致。

普通生产构建不包含测试代码、测试数据、Sable 本体或航空学本体。原有小弹药盒和普通结构库存补给继续保留。

首版不自动消费特殊组件弹药，不开放移动弹药库原生 GUI。多节列车、跨维度、多人同时打开库存、嵌套 Sable/Create 结构、高速自由飞行及异常放置失败等边界仍需专项测试。本轮保存验证为 NBT 往返与实际拆卸，未执行完整服务器重启迁移。

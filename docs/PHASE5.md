# 动态结构齿轮修复与列车服务端验证（alpha.6）

环境：Minecraft 1.21.1、NeoForge 21.1.228、Create 6.0.10、官方 TaCZ 1.2.0。本轮开发运行目录还安装了航空学整合包 1.3.2 和 Sable 2.0.3。

## 齿轮错位

用户反馈：物理结构正常，但 Create 动态结构运行时，机械臂底部齿轮偏离原位。

动态渲染路径中，机身渲染结束后提前弹出了最外层 actor 矩阵；齿轮随后调用互相抵消的 uncenter/center，再绕局部原点旋转并平移，造成齿轮绕错误中心运动。finally 还会多退一层，破坏调用方提供的结构矩阵。

alpha.6 将 actor、机身、关节和齿轮的矩阵层级独立配对。齿轮始终围绕本方块中心旋转，吊装时继承倒置方向。夹爪两半也恢复到头部关节下，避免继承错误的机身坐标。物理结构使用的静态方块渲染路径未改动。

客户端验证包含：

- 24 种齿轮变换组合：地面/吊顶、六个转角、静止/旋转平移的调用方坐标；检查中心不漂移、轴向正确、调用方矩阵保持不变。
- 4 次完整动态渲染调用：空手/装枪、地面/吊顶，使用实际部分模型和虚拟渲染世界，检查渲染返回后的调用方矩阵。
- 保留 68 个 TaCZ 标准模型和 4 种动态枪械安装矩阵对比。

## 列车服务端测试

测试由专用服务器自动执行，无玩家连接，也没有客户端发射击请求。

使用 Create 原生 `Train`、`Carriage`、`CarriageContraption`、`CarriageContraptionEntity`、`TravellingPoint` 和 `TrackGraph`。从真实世界的转向架、黏液块和装枪机械臂调用车厢装配，再由铁路管理器创建和运行车厢实体。测试直接构造独立轨道图；弯道使用真实 BezierConnection，不用轴承实体代替列车。

四种运行线路：直线、斜向吊装、约 14° 上坡、弯道。每辆车先前进，再倒车，停车后再前进。停车期间保留装配时捕获的机械臂动力。枪内装入 30 发并挂载有限弹药箱，记录枪内、膛内和箱内总弹药；目标每 tick 恢复生命，避免提前击杀导致后续运行阶段没有可射目标。

验证：

- 原生车厢实际移动，弯道实际改变车厢朝向。
- 自主开火和实际伤害事件。
- 真实弹丸起点与实时世界枪口一致。
- 总弹药减少量等于真实发射的弹丸数。
- 倒车、停车期间持续开火。
- 车厢 NBT 重读保留枪械和弹药状态。
- 车厢实体移除后清理 FakePlayer 和手持物。

复现命令：

```powershell
./scripts/build-baseline.ps1 -JavaHome 'C:/Program Files/Java/jdk-21' -VerifyTrainSentry
./gradlew.bat -PsentryClientSmoke runClient --console=plain
```

客户端自动测试使用 `phase3-validation` 测试世界并在完成后退出。运行目录已装有 Sable 时不必再传 `SableJar`。

## 范围边界

服务端可以验证列车运行、射击和保存逻辑，不能验证玩家实际看到的画面；齿轮问题通过独立客户端渲染测试验证，仍欢迎在原先出现错位的结构上确认视觉结果。

本轮没有覆盖车站界面装配、时刻表、多节列车、传送门跨维度、两名独立玩家观察、完整服务器重启迁移及其他列车扩展模组。轨道图测试不等于这些流程全部通过。

客户端与服务器建议一起升级 alpha.6；协议仍为 3。

## 最终结果

- 专用服务器：38 项通过，0 失败，四辆原生车厢均实际移动；全程无人连接。
- 直线、吊装斜向、上坡、弯道分别发射 181、181、177、173 发；初始总弹药均为 231，剩余 50、50、54、58，守恒一致。
- 四种场景的实际弹丸起点与实时枪口误差均为 0；均记录到实际伤害事件。
- 倒车、停车射击及车厢 NBT 重读、实体移除清理均通过。
- 客户端：24 种齿轮姿态、4 次完整动态渲染调用、4 种枪械安装变换均通过；68 个标准枪械模型对比通过，2 个既有回退模型跳过，收到 70 个枪口配置。
- 生产构建与产物检查通过，测试类和测试资源未打入发布 JAR。

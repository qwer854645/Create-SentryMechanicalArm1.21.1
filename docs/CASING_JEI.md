# alpha.22：移除旧制造链、弹壳提示与 JEI

验证环境：Minecraft 1.21.1 / NeoForge 21.1.228 / Create 6.0.10 / 官方 TaCZ 1.2.0 / Java 21；开发端 JEI 19.21.0.247。

## 本版变更

- 完整移除旧待加工弹壳/子弹模板、铜板与火药加工链：删除物品、配方序列化器、旧加工钩子、旧教学和资源。保留新回收弹壳、再装填中间件及单发再装填。TaCZ 自带工作台配方与机械手装填弹药盒保留。
- 移除旧 ammo_crafting / dynamic_recipes 制造配置。现在由服务端 [reloading] enabled 单独控制再装填；autoFromTaCZ 控制自动推导成本。仍需启动配置 [casings] enabled 为 true 才注册弹壳与中间件。掉落开关独立。
- 弹壳提示仿照子弹：灰色用途、蓝色斜体枪包来源；高级提示才显示 Ammo ID。中间件说明可以单独合成取回弹壳，材料不退还。
- JEI 为回收弹壳和再装填中间件注册口径子类型，排除改名和数量的干扰。实际中间件收藏区分配方和步骤，配方查询按口径匹配；序列过渡模板携带口径组件，便于识别。
- JEI 列表随服务端允许的弹壳集合更新，去掉无口径、特殊弹药和中间件占位条目。JEI 仍为可选依赖。
- 保留 38% 裁剪、现有亮度、9mm 分类图标与分类顺序。网络协议升级为 9，客户端和服务端应一起更新。

## 为什么此前 JEI 把不同弹壳合并

TaCZ 和本模组都采用一个注册物品加口径数据的方式，但数据格式不同。当前 TaCZ 的子弹将 AmmoId 字符串存入 Minecraft 的 minecraft:custom_data；本模组用有持久化与网络编解码的 sentrymechanicalarm:casing_ammo ResourceLocation 组件。

JEI 的子类型解释器按具体 Item 注册，不会因为数据格式相似就自动继承 TaCZ 的注册。此前缺少本模组弹壳的解释器，因此折叠了口径；本版补齐注册，并在真实 JEI 运行时验证。无需改成 TaCZ 的 IAmmo，否则空壳可能被误当成可装填子弹。

## 验证

- 真实客户端 JEI：37 种允许弹壳均有独立身份；9mm 用途查询仅返回对应的再装填序列；改名/数量不改变身份；中间件进度、普通/高级提示和枪包来源通过。
- 客户端模型 226 项通过，6 个特殊模型使用既有回退；弹壳图标、分类和中间件四种渲染上下文通过。
- 服务端新再装填 15 项通过，包括真实溜槽/漏斗/箱子、置物台/机械手/冲压、单发射击回收闭环、序列编解码及数据包重载。当前测试组合生成 17 种自动成本配方。
- 服务端射击 68 项、抛壳 15 项、静态哨戒臂 31 项通过。
- 不安装 JEI 的服务端：启动总开关开启时 14 项通过；关闭时 9 项通过，确认物品和分类不注册。

测试属于隔离开发环境，不是对所有整合包、多人会话或移动工厂的完整验收。现有自动成本仍保守保留原材料并向上取整，可能比新造弹药更贵；自定义成本沿用 docs/CASING_RELOADING.md 的数据包格式。

## 升级注意

旧 sentrymechanicalarm:unfinished_ammo 已不注册，旧模板/在制品及其加工链不迁移。更新已有世界前备份存档。新 empty_casing 和 reloading_casing 的物品 ID 与口径组件保留。旧制造配置不再控制任何生产流程；需要停用再装填时设置 [reloading] enabled = false 并重新加载配方。

本轮客户端自动检查使用独立 alpha22-jei-validation 世界，没有加载原手动测试世界。开发客户端未留在运行状态，未修改 F: 的整合包。

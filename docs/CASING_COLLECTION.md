# alpha.35：弹壳收集器与玩家背包收集

## 弹壳收集器

新增存储方块 sentrymechanicalarm:casing_collector，中文名“弹壳收集器”。27 格普通库存，右键使用原版三行容器界面；支持漏斗、Create 漏斗等物品接口，并输出库存比较器信号。可以存放普通物品，因此自定义抛壳物也无需逐项适配。

合成材料为一个箱子、两个安山合金、两个铁锭。模型仅引用 Create 的机壳和置物台等材质，没有复制 Create PNG。

不新增机械臂收集模式配置。满足原有抛壳条件并通过概率后，动力臂自动尝试将本次生成的物品直接存入收集器；没有创建地面物品再吸取的过程，也不吸取附近原有掉落物。

- 静态世界：只查找哨戒动力臂上下左右前后的六面相邻收集器。
- Create 动态结构、矿车和列车：查找同一个 Contraption 内的收集器，优先距离近的；不使用普通箱子，不查找外部结构或地面容器。
- Sable/机械动力航空学：实际方块实体按同一个子结构 UUID 查找已加载收集器，不跨结构收集。可选 VS2 路径按船体 ID 隔离。
- 多个收集器可依次接收余量；全部装不下或没有收集器时，仅剩余部分按原有抛壳方式掉落。

普通掉落仍遵守原有区块实体数量上限和寿命设置。先收集、后处理掉落上限，地面已满不会阻止容器接收。

## 保存、移动与物流

静态及 Sable 方块库存使用原版 Container 数据保存；Create 动态结构使用独立的 CasingCollectorMountedStorage 类型及原生 SimpleMountedStorage 协议，接入结构保存、容器交互、便携式存储接口和拆卸回写。射击只写入当前结构的这份移动库存，不同时写方块 NBT 副本，避免两套库存并存。

静态库存变化正常标记保存并更新比较器；正常拆除方块会像箱子一样掉出库存。Create 装配移动时不主动散落库存。船上原位容器界面使用投影后的世界坐标判断距离。

检索只使用已加载方块或当前结构的存储记录，不为收集器远程加载区块。收集器本身是普通存储方块，即使关闭弹壳输出，也保留其既有库存及存储功能。

## 玩家配置

世界 serverconfig/sentrymechanicalarm-server.toml 的现有 casings 段新增：

```toml
[casings]
players = true
playersToInventory = true
```

alpha.36 起 playersToInventory 默认为 true，设为 false 可恢复地面抛壳。开启后，按物品正常堆叠规则插入玩家背包；部分放入时，剩余部分使用原版 /give 的溢出行为：由玩家位置掉落、无拾取延迟、指定该玩家为拾取目标，不静默丢弃。

成功放入背包不创建真实掉落实体。背包溢出使用原生 /give 式物品实体，不再套用弹壳地面数量过滤或自定义寿命，避免背包满时额外吞掉物品。正常抛壳模式和机械臂的地面余量仍使用原抛壳限制。

players=false 仍表示完全不生成玩家弹壳，不等同于选择地面模式。

## 与自定义抛壳的关系

先由 alpha.34 规则决定物品、组件、数量和概率，再进入本版收集流程。其他模组物品、其他口径弹壳以及超出单堆的数量都走同一逻辑，组件不会被换成默认口径。

全局注册、抛壳总开关、玩家/动力臂/其他生物来源开关及有限弹药消耗确认继续保留；创造模式和无限弹药不产回收物。其他生物仍沿用地面输出，不使用玩家背包或哨戒收集器。

## alpha.37 材质更新

收集器顶部直接引用 create:block/funnel/andesite_funnel 的 Back 面区域（UV 0,0–6,6）；其余五面及粒子统一引用 create:block/andesite_casing。按原模型的 UV 取背面部分，避免把漏斗整张拼接图铺到顶部。没有复制或内嵌 Create PNG。

## alpha.38 侧向安装背面修正

> 当前模型已在 alpha.40 改为完整机壳加单独的背面薄面板，移除 alpha.39 误加的整套漏斗结构；见 [PONDER_FIX_AND_TEXT.md](PONDER_FIX_AND_TEXT.md)。

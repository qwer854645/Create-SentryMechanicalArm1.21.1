# 第三阶段：枪口、弹道与枪械模式

版本：1.4.0-alpha.4。日期：2026-11-07。
依赖保持 Minecraft 1.21.1、NeoForge 21.1.228、Create 6.0.10、官方 TaCZ 1.2.0。

## 改动

### 服务端定义枪口

新增 SentryGunProfiles 和 SentryGunGeometry。

- 服务端从已加载枪包读取 display、Bedrock 模型骨骼及第三人称缩放，推导默认静止姿态的枪口位置与方向。
- 共用动力臂关节、吊顶和特殊握持变换，服务端使用双精度局部计算，客户端渲染复用同一握持变换。
- 通过新的服务端到客户端数据包同步配置，在加入游戏及数据包重载时更新；退出时清理客户端缓存。
- 不使用客户端上报的枪口来决定静态炮塔的实际射击。
- 当前默认枪包 70 把枪，68 把具有可解析的标准枪口节点。RPG7、M320 没有标准节点，使用显式回退值。
- 非标准或旧模型可通过服务端数据包指定局部枪口位置与方向；错误、非有限或越界数据不会产生失控坐标。

网络协议版本升为 2。服务端与客户端应同时升级到 alpha.4，不能混用旧版。

### 弹丸与视觉

- 移除通过 rifle、pistol 等枪名片段猜测弹丸类型的代码。是否有可见弹丸模型来自实际弹药 display 数据。
- 普通子弹与 RPG 等武器均从统一枪口生成真实 TaCZ 弹丸，不再根据视觉类型选用不同的射手位置。
- 修正旧位置计算的俯仰符号，开火门槛同时检查水平与垂直方向。
- 枪口表现记录真实弹丸的出生位置与初始方向，不再使用已经恢复的 FakePlayer 位置生成开火包。
- 有原生可见弹丸或原生示踪弹时，停止叠加额外示踪线；其余辅助示踪线使用服务端弹丸起点与方向，移除额外的 0.6/0.8 格起点偏移。
- 调整渲染法线变换，使其随共用枪械握持矩阵更新。

### 延迟连发与状态

- M16 等武器的后续连发由 TaCZ 的周期任务执行。射手持续处于统一枪口位置，射击方向供应器读取当前炮管姿态。
- 实际弹丸生成时立即提交已消耗的枪械及弹药箱状态，避免下一 tick 用旧副本覆盖连发弹药消耗。
- 每次真实击发发送一次表现数据，霰弹的多个弹丸不重复播放多次枪口效果。
- 断电取消尚未执行的连发；销毁射手时清空手持枪，使原生延迟任务停止。
- 按 TaCZ 数据处理 AUTO、HOLD、DELAY 蓄力；每游戏 tick 最多累积一次，遵守蓄力阈值、冷却期间蓄力和开火后的进度削减。
- 半自动与全自动的等待时间读取原生射击间隔及修正值，原生冷却仍作最终约束。
- 背包直读武器使用弹药箱供弹，不再把这种武器的“无需向弹匣装填”当作一次成功换弹。

## 验证

### 继承回归

第二阶段静态流程 31 项通过，包括实际 Create 马达供能、断电恢复、遮挡、保存、掉落、补弹与网络范围。

### 服务端第三阶段：68 项通过

测试使用真实 TaCZ API 和弹丸，不以“shoot 返回 SUCCESS”代替真正击发。

- 13 个射击场景：Glock 17、AK47、M16A4 连发、AWP 栓动、M870 霰弹、RPG7、Rhino 357 蓄力、迷你机枪、抬高目标、吊顶、112 格目标、HOLD 蓄力夹具、DELAY 蓄力夹具。
- 检查实际击发、有限弹药守恒、真实弹丸出生位置、方向及目标受伤。
- 另外检查数据包枪口覆盖、非有限数据拒绝、已知骨骼变换、吊顶镜像、俯仰对准、远坐标精度、网络编码往返、蓄力等待及断电取消延迟弹丸。
- 第三阶段测试中记录的枪口与实际弹丸出生位置误差为 0；原生散布保留。
- 112 格 AWP 场景已记录实际目标受伤。测试通过火控名单隔离各目标，避免选中相邻测试区域的近处目标。
- HOLD/DELAY 枪械数据是测试夹具，正常发布包不携带。

运行：`./scripts/build-baseline.ps1 -JavaHome '<Java 21目录>' -UseWindowsProxy -VerifyGunGeometry`。

### 客户端模型与同步

使用测试存档副本 phase3-validation 自动进入单人游戏，对比 TaCZ 原生 GunItemTransforms 与服务端配置。

- 68 把标准模型通过，2 把缺少标准节点的发射器跳过精确模型比较。
- 最大局部模型枪口误差约为 1.6e-7 格。
- 客户端实际收到全部 70 把默认枪械的服务端配置。
- 测试使用存档副本，未修改原“新的世界”存档；完成后自动退出测试客户端。

重复运行需要已有 phase3-validation 测试副本：`./gradlew.bat -PsentryClientSmoke clean runClient`。
必须检查 PHASE3_CLIENT RESULT，不能只看 Gradle 退出码。

## 枪口覆盖格式

文件位置为 `data/<枪械命名空间>/sentry_muzzles/<枪械路径>.json`。
例如 `example:custom_rifle` 对应 `data/example/sentry_muzzles/custom_rifle.json`。

```json
{
  "muzzle": [0.0, 0.0, -0.75],
  "forward": [0.0, 0.0, -1.0],
  "visible_projectile": false,
  "minigun_mount": false
}
```

上述数值仅为格式示例，不是对特定枪械的校准结果。muzzle 位于 TaCZ 第三人称握持后的局部坐标中，单位格，尚未乘动力臂的 1.5 倍缩放。
forward 会归一化，visible_projectile 只控制辅助示踪线策略，不改变真实弹丸生成方式。字段可以部分覆盖。
修改服务端数据包并执行 /reload 后，会重新计算并同步配置。

## 限制与后续

- 仍为 alpha。没有证明所有第三方枪包、换皮模型、外挂附件、自定义 Lua 弹丸或特殊 model_type 都已兼容。
- 默认 RPG7、M320 使用回退枪口；RPG7 已验证开火和命中，但未宣称回退点精确贴合模型喷口。
- 客户端验证覆盖静止模型数学变换与数据同步，不等于所有动画插值、所有视角及两台独立客户端的画面验收。
- 原生重力、阻力、散布和伤害规则保留；没有实现通用的弹道下坠补偿或移动目标提前量。
- 共用几何也接入了动态结构局部枪口，但移动结构控制、库存及 Sable 坐标仍属于后续专项，未在本阶段宣称验证通过。

## 输入与环境

用户提供的两个 ZIP 原样复制到开发运行目录的 tacz 文件夹，未改动原文件，不打入发布 JAR、源码 ZIP 或 Git。测试时同时加载默认枪包和这两个枪包，没有导入用户的实际存档或整个整合包。

- Ars Armorer_v1.0.1_for117.zip，SHA-256：6AEE83F71962F75188C646DBA81F917E13646018AEB29ADF21876C8D4F151D98。
- Applied Armorer-v1.1.4.1-for114+.zip，SHA-256：3CCFF2FC237AB4B71B03F900616F9DFECC17B34DBE60C89C625223A6C5F126B1。
- Minecraft 1.21.1 / NeoForge 21.1.228 / Create 6.0.10 / TaCZ 1.2.0 / Java 21；开发环境保留航空学 1.3.2、Sable 2.0.3。

运行时共加载 91 个枪械索引、32 个弹药索引；新增部分为 Ars 8 种武器、1 种魔力资源，Applied 13 种武器、6 种弹药。

## Ars：特殊脚本枪包

Ars 的弹药是 ars_armorer:mana，没有 shell 模型或贴图。脚本以 shootOnce(false) 发射，再自行处理魔力消耗、延迟和恢复；普通法器需要 GRIP 槽事件符，迫击炮和钻头另有逻辑，飞刀还会延迟扣除与恢复资源。

验证覆盖八种武器的全部声明模式，并加一个不装事件符的手枪负向对照。有效施法场景安装 spell_damage 事件符；只使用该配件作为基础代表，没有穷举其他事件符、触发器和修饰符组合。

结果：武器原生脚本均可击发，魔力按脚本恢复且没有被每 tick 重复恢复。无事件符的普通手枪不产生弹丸，符合枪包条件。mana 不会变成实体弹壳，也不会因一次射击产生多个可回收物品。

限制：迫击炮在本靶场记录到 6 次成功击发、48 个弹丸，但未记录到目标受伤。它的脚本额外施加向上散布，当前修复只解决炮管方向与对准，不是完整的曲射/弹道命中方案。钻头和飞刀没有标准枪口骨骼，使用已有枪口回退，不能保证视觉出口与伤害起点精确重合；没有验证钻头挖掘和飞刀完整视觉行为。

## Applied：常规弹药与部分特殊逻辑

三种石英弹药自动识别出可回收弹壳：cluster_quartz_bullet、etched_quartz_bullet、hard_core_quartz_bullet。名称、模型和贴图都从实际枪包读取。

fluix_battery 与 melee 没有弹壳声明，不产出弹壳。fluix_infused_grenade 虽然有原生 shell 资源，仍按当前默认保守规则不产出；如确认其回收语义，可通过 data/applied_armorer/sentry_casings/fluix_infused_grenade.json 显式设置 enabled=true。

测试覆盖全部声明射击模式，包括双持手枪的单发/连发、普通连发、霰弹、手动拉栓、能量弹丸及 HMG 加速脚本。有限弹药的减少量与实际成功击发数相等，三个物理弹药类型的弹壳总数与击发数一致。该轮共记录 2064 个可回收弹壳，魔力、电池、近战和默认排除的榴弹没有混入。

近战 task_manager 的射击函数本身为空；哨戒臂不会自动挥砍，作为无弹丸负向对照，不把它算成可自动近战使用。哨戒臂沿用即时补弹机制，不能把本轮结果解读为玩家双持左右手换弹动画与所有原生换弹脚本已验证。

## 本轮发现并修复的通用问题

### 非标准模型方向无法对准

原算法根据目标方向直接设置关节，默认枪包的静止枪轴大多接近标准轴。Ars 迫击炮实际枪轴有约 45 度俯仰偏移，Applied 双持手枪有约 15 度偏航偏移，因此旧版会长期达不到 1 度开火对准条件。

新增实际模型轴向的关节逆解，考虑枪包 hand/muzzle 姿态、吊装、当前关节与特殊握持。模型枪口与真实弹道仍共用一套变换，没有改成跳过对准，也没有针对枪包 ID 硬编码角度。

修复后迫击炮可以成功击发；双持手枪单发和连发均持续射击并命中。增加 24 个数学组合覆盖默认、加特林、上述两个偏转模型、地面/吊顶及多个目标方向。

### 额外节流覆盖枪包加速脚本

旧版按枪械基础射击间隔设置哨戒臂等待，HMG 脚本对原生 shootTimestamp 的缩短无法完整生效。改为读取 TaCZ 原生剩余射击冷却，保持原生判定和脚本时间戳的约束。

实际 HMG 后段平均间隔为 2 个游戏 tick，在 20 TPS 下约 100ms；加速断言通过。没有通过直接改 RPM 或跳过原生冷却实现加速。

## 验证结果与边界

- 专项：27 个场景，116 个断言组全部通过。包括模型方向逆解、魔力恢复、无事件符对照、真实弹丸、有限弹药、原点一致、弹壳计数、脚本持续可用、HMG 加速和断电取消后续击发。
- 客户端：91 个同步枪械配置，86 个标准模型位置比较通过，5 个使用回退；最大位置误差约 2.96e-7 格。
- 默认枪包 24 套、Applied 4 套原生弹壳模型/贴图成功读取，Ars 没有原生弹壳。预览包含无壳类型的通用外观测试样本，图片不是实际掉落名单。
- 当前版本为 alpha.12，协议保持 6；建议两端一起更新。

这轮针对哨戒臂射击、弹壳系统与模型加载，不是整个整合包完整验收。没有穷举所有配件组合，没有双独立客户端实战观战、特殊工具完整行为、任意旧存档迁移或强杀恢复。魔力/电池等特殊资源的制造配方与整合包脚本需要单独审核，本轮不将其描述为已平衡或已完整兼容。

## 复现

将用户提供的两个原始 ZIP 放入开发 run/tacz，使用 Java 21：

- 服务端：gradlew.bat runServer -PsentrySmoke=gunpacks；每次使用独立测试世界。必须检查 GUNPACK RESULT，不能仅看 Gradle BUILD SUCCESSFUL。
- 客户端：gradlew.bat runClient -PsentryClientSmoke -PsentryClientReloadSmoke -PcasingClientSmoke -PgunpackClientSmoke。

本轮新增测试代码不进入正常发布包，第三方枪包文件也不进入 Git 或交付源码。

# 动态结构与 Sable 兼容修复（alpha.5）

目标环境：Minecraft 1.21.1、NeoForge 21.1.228、Create 6.0.10、官方 TaCZ 1.2.0。额外实测 Sable 2.0.3，Companion 1.6.0。

## 已修复

- Create 动态结构复用静态哨戒机械臂的 TaCZ 控制器，统一装弹、拉栓、冷却、连发、蓄力与弹药保存。客户端提交的旧射击请求不再触发开火。
- 保持 actor 方块坐标为结构局部坐标；目标搜索使用世界坐标，瞄准时将目标逆变换到结构坐标，真实枪口同时变换位置和方向。
- Sable 使用承载方块所属船体的完整 Pose 转换枪口，包含俯仰、偏航和横滚。不再用固定高度近似枪口，也不再把世界射线的终点单独变换回船内。
- 延迟连发在每次实际开火前更新 FakePlayer 枪口位置，避免结构旋转后后续子弹从上一 tick 的枪口发出。几何更新不覆盖已经消耗的弹药。
- 修复 actor 状态与 Create 结构方块 NBT 脱离的问题，防止保存、重读或拆卸恢复旧弹药；停止和实体移除时清理射手，取消残留射击。
- 服务器定期向跟踪结构的玩家发送角度、枪械与弹药状态；客户端插值显示。射击、拉栓及装弹声音采用真实世界位置。
- 动态枪械渲染采用与服务器枪口一致的安装矩阵，保留结构旋转和 actor 偏移，统一吊装和加特林的变换。
- 结构仓库存有匹配弹药箱时，可将其提取并装入空的挂载槽；已有普通挂载箱可从库存散装弹药补充，容量遵循 TaCZ 配置。库存提取成功后才增加弹药，空箱可重新绑定口径。
- 保留装配时的转速和射程；无捕获转速时按结构实际运动提供驱动，避免静止且无动力时默认凭空获得转速。

## 验证方式

`MovingSentrySmoke` 使用真实 Create BearingContraption 装配与 ControlledContraptionEntity actor 调度。覆盖地面自动步枪、吊装三连发和栓动枪，结构持续旋转；验证真实弹丸、实际伤害事件、弹药守恒、枪口坐标、结构 NBT 重读、拆卸回世界与射手清理。无需玩家在线或客户端发送射击请求。

Sable 测试通过其 `SubLevelAssemblyHelper` 装配真实船体，带机械臂、齿轮和创造马达，使用真实船内方块 tick。测试期间暂停重力物理、持续改变船体偏航并施加俯仰和横滚，以隔离坐标问题；验证真实弹丸、伤害、弹药守恒和世界枪口位置。另检验 Pose 缩放及大坐标的正逆变换。

客户端验证读取 TaCZ 原生模型，并比较 Create 原生 ContraptionMatrices 与公共枪口变换，覆盖普通枪、加特林与吊装。

复现服务器兼容测试：

```powershell
./scripts/build-baseline.ps1 -JavaHome 'C:/Program Files/Java/jdk-21' -VerifyMovingSentry
./scripts/build-baseline.ps1 -JavaHome 'C:/Program Files/Java/jdk-21' -VerifyMovingSentry -SableJar '<本地 Sable 2.0.3.jar 绝对路径>'
```

普通 `clean build` 不包含测试类或测试资源；`SableJar` 仅用于本地运行，不会打包进修复版。

## 使用与边界

- 客户端和服务器均安装 alpha.5，删除旧版同名模组。网络协议已升级为 3，不能与 alpha.4 混用。
- 先在方块状态装好枪和弹药，再装配 Create 结构。Sable 不必安装；需要船体时自行安装 Sable 2.0.3。
- 已实测的是 Create 轴承 actor 与 Sable 船载方块两种路径。Create actor 嵌套在 Sable 船上的组合、活塞/龙门架/矿车/列车各自的完整流程、多玩家晚加入后的视觉表现，以及其他 Sable 版本仍需专项实测，不能据此声称全部兼容。
- 当前补给支持库存弹药箱装入空挂载槽、库存散弹填充已挂载箱；不直接把仓库中另一只箱子的内容倒进已占用的挂载箱。
- Sable 运行测试隔离了重力自由运动，尚未覆盖高速自由飞行、船体缩放后的实战弹道、多人网络延迟和各种渲染优化模组。

精确测试结果和原始日志随 `outputs/evidence` 一起交付。

# 第八阶段：配方与资源重载修复（alpha.9）

环境：Minecraft 1.21.1、NeoForge 21.1.228、Create 6.0.10、官方 TaCZ 1.2.0；开发环境同时安装 Sable 2.0.3 与 Aeronautics 1.3.2。

## 配方生命周期

动态弹药配方在开服时生成，并在服务端资源重载完成、TaCZ 配方与标签初始化之后、原版向玩家同步配方之前重新生成。普通玩家登录只同步现有数据，不重新生成配方，也不清理其他哨戒臂的射手。

生成器只移除自己上一轮生成的实际配方对象，不按命名空间批量删除。数据包显式提供同 ID 配方时，数据包优先；重复重载不叠加配方；禁用动态配方后仍保留数据包配方；移除覆盖包后恢复自动生成。保留现有普通弹药的配方 ID，并按口径排序处理旧编码碰撞。

配方查询与机械锯口径过滤改用 RecipeManager 公共 API，移除对 byType 字段的反射访问；删除原先只有日志、没有实际重载功能的 SentryRecipeHandler。

## 生产流程与材料核算

- 工作台的弹药模板配方每次产出 1 个模板，与原版每个输入槽扣除 1 件物品一致；不再根据输入整堆数量扩大产出。
- 机械手用弹药处理铜板时，最多处理弹药实际能够支付的数量，并保留未处理铜板。
- 旧传送带加工按实际加工数量扣除铜板或火药；材料不足时拆分已加工部分和余料；加工冷却写回物品组件。
- 旧加工进度只能记录铜板与一次火药。因此仅在原材料确实全部为铜板、一次火药且进度可表示时生成独立压制配方。铁板、TNT 等其他材料的弹药使用完整序列装配，避免通过廉价铜板跳过所需材料。
- 新增 unfinished_ammo 原料类型，直接按口径、最低铜板进度、是否加火药匹配。它能进行 JSON 与网络编解码，避免把布尔 NBT 编成数字后，因具体标签类型不同而拒绝合法模板。
- 无效 AmmoId 安全返回不匹配；分类回退规则按最长关键字优先，消除 Map 遍历顺序影响；无法解析材料的 TaCZ 配方走分类回退，不静默丢掉材料步骤。

未重新设计 RAW/GCD/FIXED 配方缩放和平衡参数；这些选项仍沿用现有配置。

## 标签与缓存

Create 标签目录迁移为 1.21 的 tags/block 和 tags/item，使 wrench_pickup、fan_transparent、upright_on_belt 能被加载。

服务端重载会清理旧射手，使后续射击重新创建 TaCZ 操作者和配件参数缓存；保留哨戒臂自身枪械、配件与弹药数据。旧连发任务不能继续通过失效射手开火。枪口参数继续由服务器重建，并在 TaCZ 数据同步之后发送给客户端。

客户端资源重载清理哨戒臂的显示实例和弹道显示缓存。客户端单独重载资源不会清空服务器同步的枪口参数；服务端枪包数据发生变化时，仍需执行服务端重载。

## 验证方式

隔离世界中执行四轮真实 MinecraftServer.reloadResources：启用覆盖包、重复重载、禁用动态配方、移除覆盖包。覆盖包同时更改 TaCZ 9mm 材料与产出、覆盖一个自动配方 ID、修改 Glock 枪口参数。

服务端专项 24 组通过，包含全部 25 种默认弹药通过 Create 原生配方选择和逐步加工结算逻辑完成序列装配；重载后的新材料与产出也通过同一流程。另验证合法/错误口径、未支付火药、模板堆叠、加工拆分、旧射手失效、弹药保留、JSON/网络原料编解码及玩家登录边界。

客户端实际执行 Minecraft.reloadResourcePacks，通过旧显示实例失效、新 TaCZ 模型实例生成和同步枪口数据保留检查；随后 68 个标准模型对比通过，2 个模型继续使用既有回退。

这不是实体传送带、机械手、压机组成的完整生产线长时间吞吐测试。双独立客户端的实际配方界面同步、任意第三方枪包、加工到一半时修改装配步骤的迁移仍未覆盖。修改配方后，旧半成品将按 Create 当前配方语义处理；不承诺跨任意步骤变更恢复原进度。

## 使用与复现

新增原料注册类型，网络协议从 4 升为 5，服务端与客户端请一起更新 alpha.9。

服务端重载专项：scripts/verify-reload.ps1；每次默认创建独立测试世界。客户端专项：gradlew.bat runClient -PsentryClientSmoke -PsentryClientReloadSmoke。正常构建不包含测试类或测试世界。

本版修正两项通用规则：制壳不再要求能完整解析整发弹药；再装填不再将每一份普通材料展开成独立机械手步骤。

## 制壳规则

以前只有完整成本能推导且有金属预算余量的弹药进入模具列表，当前测试组合因此只有 15 种可制造，而可回收弹壳有 37 种。

现在先独立读取原方中明确的铜/铁/金材料，原方中的青金石或其他特殊配料不再阻止读取壳体金属。有完整自动再装填成本时，继续保留原来的整发金属预算上限；只有部分原方可理解时，仅使用明确的制壳金属份额，不声称已经核算整发经济成本。

对仍无法取得可靠金属预算的允许弹壳，默认使用明确的通用铜壳规则：一粒铜粒制造一枚弹壳。这是可配置的游戏平衡规则，不是假装从未知枪包推导出的原材料。特殊无壳、能源等类型仍由现有弹壳允许集排除。

当前五个测试枪包组合：37 种允许弹壳全部有模具配方，其中 27 种采用原方金属规则，10 种采用通用铜壳规则。原来能制造的 9mm 等口径继续使用原预算产量，例如 9mm 一粒铜粒两壳。

```toml
[casingManufacturing]
enabled = true
allowGenericCopperFallback = true
fallbackCasesPerCopperNugget = 1
```

关闭 allowGenericCopperFallback 后只保留可从原方金属得到的配方；fallbackCasesPerCopperNugget 范围 1–64，只改变通用规则，不改变原预算产量。修改后执行 /reload。

能够制造空壳不等于能自动再装填整发弹药。复杂或未知弹药仍需要明确的再装填材料配置，不能用一条通用铜壳规则免去特殊弹头/装药成本。本版没有扩展为所有 37 种弹药猜测整发制造配方。

## 装配序列

原算法把每份材料分成一步，例如 12g：底火一次、少量火药十次、铜粒四次、铁粒一次、冲压一次，共 17 步。

现在将连续且相同的普通可消耗材料合为一次加料，12g 改为五步：

1. 安装一个通用底火。
2. 一次加入十份少量火药。
3. 一次加入四粒铜粒。
4. 加入一粒铁粒。
5. 冲压产出一发 12g 子弹。

当前 15 条自动再装填配方均为 4–5 步，9mm 原来已经是四步，保持四步。5.56 从六步压缩到四步。材料实际总量不减少：底火原有的铜与火药成本也没有变化。

## 实际扣料与边界

原生机械手通常只扣一个物品，不能只把 JEI 显示改成堆叠数量。本版新增 counted_deploying 自定义 Ingredient：保留材料类型匹配与显示数量，在原生机械手执行回调开始前检查库存数量，满足后在原生扣料位置一次扣齐。库存不足时不推进在制品、不扣部分材料，补齐后再继续。

同一个原生回调适用于置物台/传送带加工路径。本轮实物夹具验收的是置物台，尚未搭建完整传送带厂线或移动工厂；第三方代加工设备不在本轮验收范围。

只有可堆叠、无耐久消耗、无容器返还的普通原料才合并。工具、容器和复杂自定义原料保留原来的行为；不会为缩短步骤而丢弃它们的语义。显式数据包的普通材料也可合并，但数量不变，顺序仍按相邻材料保留。

Ingredient 的类型匹配不按库存数量拒绝，这样原生带上有相应材料但数量不足时仍能保持加工位置；执行回调负责足量检查。数量语义需要本模组回调支持，不能把这种 Ingredient 当成任何第三方机器都原生理解的 SizedIngredient。

# alpha.24：底火零件生产与单枚再装填

> alpha.26 已接入自有物品贴图，见 [ART_DIRECTION.md](ART_DIRECTION.md)。下文为 alpha.24 功能记录。

环境：Minecraft 1.21.1 / NeoForge 21.1.228 / Create 6.0.10 / 官方 TaCZ 1.2.0 / Java 21；开发客户端使用 JEI 19.21.0.247。

## 共用零件线

1. 一粒 Create 铜粒经机械动力冲压，产出八个底火壳（primer_cup）。
2. 机械手向一个底火壳加入一份少量火药，产出一个通用底火（primer）。
3. 将通用底火统一库存并配送给不同口径的再装填线。

少量火药沿用 alpha.23：一份原版火药在合成栏或磨石中得到 32 份。底火壳和底火均使用普通物品身份，无口径变体，加入模组主创造栏；弹壳分类页保留现有的按口径弹壳。图标暂使用原版铁粒/金粒贴图，未复制第三方模组资源。

## 各口径装配线

回收弹壳 → 机械手安装通用底火 → 机械手加入剩余少量火药 → 机械手加入金属粒等原材料 → 冲压成一发子弹。

底火必须先装；没有底火时不能直接装药绕过第一步。若整发预算只有一份少量火药，该份全部进入底火，不再添加空的装药步骤。不同数量的金属粒/少量火药以多次加料表示，始终一壳一弹。底火和底火壳不是 TaCZ 可装填弹药。

## 成本分摊

自动规则先读取原方与金属系数，按默认底火配方将每发 1/8 铜粒预留给底火壳，再对剩余铜向上取整；没有铜的原方也需要通用底火，因而增加这部分铜成本，其他金属不被错误替换。火药总份数先按 alpha.23 规则取整，再将其中一份分配给底火，后续装药少投入一份。金属系数作用于弹药自动金属预算，底火本身的固定制造配方不随口径改变。

默认 9mm：一枚弹壳 + 一个通用底火 + 一份少量火药 + 一粒铜粒 → 一发 9mm 子弹。折算底火后，长期摊销为每发 1.125 铜粒与 2 份少量火药。

50 发 9mm 长期摊销为约 6.25 铜锭和 3.125 份原版火药；原方新造 50 发为 10 铜锭与 2 火药。底火铜成本、剩余装药均已计入，金属有收益，火药仍有整数粒度损耗。实际从零生产 50 个底火需要 7 铜粒得到 56 个底火壳，剩余 6 个应保留库存，不能算成消失的材料。

自动配方比较时把底火铜也计入；所有材料均无收益或超出步骤预算的情况仍跳过。不同材料之间没有统一货币定价，因此不保证每一种原料都比原方便宜，也不保证每种整合包的市场成本相同。

## 配置、覆盖与更新

沿用 [reloading] enabled、autoFromTaCZ、metalCostMultiplier，不增加强制流体或外部模组依赖。自动配方使用新底火；显式数据包 materials 仍完全按字面执行，不被额外插入底火。作者可以自行列出 primer 等材料。修改底火壳产量或底火配料的数据包需要同时重新核算再装填成本；自动算法按本版默认的 1:8 铜粒分配假设计算。

新原料步骤改变自动配方指纹，旧在制品不能跳过底火直接续加工。旧在制品单独放入合成栏可取回弹壳，已投入材料不退还。新开工的在制品仍保存口径和原生 Create 序列进度，缺料时停留，补齐后继续。

客户端与服务端需要一起更新到 alpha.24，新物品注册必须一致。消息协议沿用 9；只更新客户端不支持服务器缺少新物品的情况。更新前备份旧世界。

## 验证范围

最终结果：服务端 28 项通过；真实客户端底火生产配方检索、两物品模型与提示、37 种弹壳 JEI 身份检查通过。客户端标准枪械模型 226 项通过，6 个特殊模型沿用既有回退。

服务端覆盖底火壳 1:8、底火 1:1 配方匹配和产量、15 个自动口径的装药分配、铜预留后取整、先装底火的顺序、原有成本与特殊类型过滤、显式数据包不隐式加费、配方重载与取消加工。

实物夹具运行铜粒冲压成 8 壳，取 1 壳由真实机械手加药，保留 7 壳与剩余药量；把这一实际产出的底火送入 9mm 装配线，完成安装底火、装药、金属加料、冲压与原生射击回收。夹具控制转速和阶段补料，不是完整传送带与漏斗供料工厂，也不是移动工厂验收。

客户端检查 JEI 底火壳冲压、底火机械手装药、两物品模型与提示、底火优先的再装填原料，以及既有 37 种弹壳子类型与口径用途检索。

## 功能边界

本版只加入底火壳和通用底火，不按口径增加底火规格；弹头继续以金属粒等材料表示。保留固体装药，不引入注液器、损坏率、清洗或整枪制造。早期一份少量火药直接冲压底火的未发布试作已替换为这里的两级生产线。

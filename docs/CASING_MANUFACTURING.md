## 使用

1. 两块铁锭和一根木棍无序合成一个弹壳口径模具。
2. 手持模具对空右键，打开口径选择窗口。支持按本地化名称或 AmmoId 搜索、分页，列表来自服务器同步的实际制壳配方。只需选择，不需要先拿到该口径子弹或弹壳。
3. 将配置好的模具放进机械手，把 JEI 显示的金属粒放到置物台或其他原生支持的机械手加工位置。机械手加工后保留模具，不消耗或磨损。
4. 新制弹壳与回收弹壳使用同一物品和口径组件，可以直接堆叠并接入现有底火、装药、金属加料与冲压序列。

空白模具和口径不符的模具不能加工。选择由服务端核验，必须实际持有模具、口径允许抛壳且存在对应制造配方；主副手分别处理。模具是一个注册物品，通过组件区分口径，持久化与网络同步保持口径。

## 自动制壳成本

本版是通用试作，只对原生 TaCZ 配方中能可靠理解成本、并有剩余金属预算的弹药生成制壳配方。沿用普通铜/铁/金材料识别、特殊弹药过滤与原有再装填成本规则，不根据枪包名或口径名称猜测。

每次机械手消耗一粒指定金属，产出整数枚弹壳。优先铜，其次铁、金；批量数量按该口径预算计算，范围 1–64。不同口径可能每粒金属产出不同数量。

对于同一份可靠原方：先折算原方每发金属量，扣除当前再装填所需的直接金属与底火铜成本，得到剩余预算；同时限制在原方金属的制壳分配份额（1 - metalCostMultiplier）内。根据这一预算向上选择每粒金属的出壳数量，确保所选制壳金属加回再装填后不超过原方的该项金属成本。多条原方存在时与自动再装填选用同一份最先可靠原方，不能借用更贵的替代原方抬高预算。没有可靠余量或需要超过 64 枚/粒时跳过。

默认例子：

- 9mm：1 铜粒制造 2 枚弹壳；装配每发再消耗 1 铜粒与一个底火，底火另摊销 1/8 铜粒。新造整发长期合计 1.625 铜粒，低于原方每发 1.8 铜粒；使用回收壳时为 1.125 铜粒。
- 5.56×45：1 铜粒制造 2 枚弹壳；合计每发 2.625 铜粒，低于原方每发 3 铜粒。

这些对比计入底火，按长期摊销计算，不含首次制造模具所需的铁、机器和物流设施。火药仍可能因单发取整高于原方；不对不同材料规定统一货币价值。底火壳批量余料保留库存。自动核算针对默认底火和原生自动再装填；数据包若覆盖底火产量或再装填材料，需要作者重新核算。

## 配置与数据包

config/sentrymechanicalarm-server.toml：

```toml
[casingManufacturing]
enabled = true
```

更改后执行 /reload，移除或恢复制造配方。该开关独立于再装填开关；关闭制造不关闭既有再装填。仍需 STARTUP 弹壳总开关启用。STARTUP 关闭时不注册模具，也不提供模具合成和制壳配方。

制壳配方 ID 为 sentrymechanicalarm:casing_forming/<弹药命名空间>/<路径>，类型 create:deploying，工具配料使用 sentrymechanicalarm:casing_mold 自定义 Ingredient（ammo_id 字段），keep_held_item 保留模具。若以数据包覆盖同 ID，作者需同时负责口径、产量与可重复工具设置。普通 TaCZ 工作台原方不修改，旧模板加工链不恢复。

只有当前存在的制壳配方才能进入口径选择列表；可抛壳不等于一定有自动制造配方。复杂模组材料和魔法/能源弹药不会通过制造入口获得猜测成本。

## JEI 与显示

JEI 区分不同口径模具，展示对应制壳用途及产物；保留 37 种弹壳的既有子类型。选择窗口支持搜索与分页。模具暂使用原版剪刀图标，未加入第三方贴图。

## 验证

最终结果：制造与再装填服务端 34 项通过；不装 JEI 的服务端 15 项通过；关闭 STARTUP 注册 10 项通过。真实客户端确认 15 个可选制造口径、JEI 模具区分与制壳配方、窗口搜索及既有 37 种弹壳检查通过；标准枪械模型回归 226 项通过，6 个特殊模型沿用既有回退。

服务端覆盖预算计算、正确/错误/空白模具、配方 JSON 与网络往返、模具存盘、保留工具、选择包主副手和非法口径校验、独立制造开关。实际置物台/机械手先验证空白模具不加工，再生产两枚 9mm 弹壳并保留模具；取一枚实际新壳接入底火生产与再装填，最后射击并回收，另一枚新壳与原有回收库存保留。

客户端覆盖 JEI 模具子类型、制壳产物配方检索、图标、同步可选口径、窗口初始化与搜索过滤。界面验证不等于多人网络下的完整鼠标交互验收。夹具控制转速和阶段补料，尚未验收完整无人值守传送带、多条分流或移动制壳工厂。
